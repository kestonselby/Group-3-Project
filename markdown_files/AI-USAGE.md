# AI Usage - policy and disclosure

This file has two halves. The **policy** is the course's rules on using AI assistants in
the group project; it does not change and you do not edit it. The **disclosure** is your
team's own record of what you actually used, and you update it before every checkpoint.

---

## Part 1 - The policy

The rule behind every line below: **you must be able to explain and modify any code you
submit.** At every checkpoint the TA asks each member about their own code. "The AI wrote
it" is not an answer your lab instructor will accept.

### The policy changes at the midterm

| When | Project work | What you may use AI for |
|------|--------------|-------------------------|
| Weeks 1-8 | Milestones 0, 1 and 2 | **Explanation only** |
| Weeks 9-12 | Milestone 3 | **AI-assisted coding allowed** |

Use a **free** model. This mirrors the practice labs, which switch at the same point.

### Weeks 1-8 - explanation only (Milestones 0, 1, 2)

You are welcome, and encouraged, to ask an AI assistant to **explain ideas**: what a class
is for, how `argparse` works, why a loop isn't terminating, what an error message means.

You may **not** have it generate code you then submit. The prototype and the application
your team hands in at Milestones 1 and 2 must be **your own work**. If a member cannot
explain code in their own slice, that is treated as a possible academic-integrity issue,
starting with a conversation.

### Weeks 9-12 - AI-assisted coding allowed (Milestone 3)

For the final milestone you may use a free AI model to help you **write** the networking,
concurrency, data-structure and algorithm code. Two conditions:

- **Do the thinking first.** Work out the design yourself - the message protocol, who does
  what, which data structure, which algorithm - and let the AI help with the
  implementation, not the decisions. Sketch your approach before you open the assistant.
- **You own the result.** You must understand every line you submit, and be able to modify
  it live at the presentation. If the AI produces incorrect code, **the errors are yours** -
  test it, and fix what's wrong.

### Always, at every milestone

- **Never paste in code you cannot explain.** This is the one rule that decides everything
  else.
- **Commits stay honest.** A commit in your name is work you did and can account for.
- **Disclose it below.** Using AI within the policy costs you nothing; not disclosing it
  is the problem.

---

## Part 2 - Your team's disclosure

Update this before **every** checkpoint, alongside `CONTRIBUTIONS.md`. One row per member
per milestone. Be specific - "explained how `asyncio.gather` works" and "drafted the
`handle_move` function, which I then rewrote to fit our protocol" are useful; "used AI a
bit" is not.

If a member used no AI at all for a milestone, write **none** in the tool column. That is
a perfectly good answer and is never held against you.

**What to write in "Used it for":** which part of *your slice*, and whether it was
explanation or generated code. If it was generated code (Milestone 3 only), say what you
changed and how you tested it.
